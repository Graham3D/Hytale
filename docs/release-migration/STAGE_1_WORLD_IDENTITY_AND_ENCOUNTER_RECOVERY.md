## Root causes and repair

The authoritative release save is `UserData/Saves/Hywind`. Its native `default` and `zone3_taiga1_world` configs have UUIDs `3d366b79-f367-419a-87b7-a8d53cde7ec0` and `6e88444d-898b-4a9d-99a6-f5f19d0257a1`. The copied, checksum-protected registry retains the matching pre-release names under `9a19439a-004d-44e6-934d-e82f0fdf662c` and `5cc8eef5-cf14-4e85-81ba-2dd651909658`. Because an existing registry suppresses first migration, both native IDs previously returned no binding and natural classification returned `WORLD_NOT_READY`.

`DifficultyRuntime` now reads installed native world configs through the release SDK UUID codec even when a registry exists. Only those two **verified old/new UUID pairs** qualify for reconciliation; the old binding must have the expected Normal campaign definition. `WorldDifficultyRegistry` writes one checksummed schema-2 transaction containing active release bindings and explicit historical bindings. Old IDs remain available through `historical(UUID)` for provenance, but are excluded from active `find(UUID)` and cannot classify a new native actor. Existing other worlds, progression scope, difficulty/profile values, and all old encounter files remain intact. An already reconciled registry is byte-identical on restart. Unknown UUIDs, duplicate native UUIDs, conflicting names/definitions, malformed checksums, and failed writes fail closed. The original `.bak` is preserved instead of overwritten. Writes still force the temporary file and atomically replace the registry; memory publishes only after the move. The exact copied v1 registry is a test fixture, not a rewritten live file.

Stage 0's original `NATIVE_SPAWN_CONTEXT` log did not include instantaneous occupancy. It proves a `CapacityRejected` but cannot distinguish 4,096 live attachments from 256 pending durable jobs. Both branches are now deterministically exercised. Source inspection found a real amplification: `HytaleEncounterRewards.added()` queued a durable context load for every known fresh SPAWN even when classification returned no authored candidate. Such new actors have no old context to restore. The existing `LOAD` path retains the lookup to restore saved actors. `HytaleEncounterRewards` now skips only the impossible fresh/no-candidate lookup and still completes the existing `HytaleDifficultyCombat` projection ticket with no profile. `PersistentEncounterRuntime` retires an attachment when its lookup returns false and no dependent transition has taken its tail; duplicate compatible add callbacks share the original immutable admission and do not reserve another job or rewrite the first spawn clock. These changes reduce useless work and retained entries without widening limits or altering reward eligibility.

`FileEncounterStore.CapacityRejected` now carries bounded occupancy and the specific `LIVE_ATTACHMENTS` or `PENDING_DURABLE_EFFECTS` boundary on these two sites. The existing one-shot `RPG_ENCOUNTER_FAILURE` message records handoff metrics for synchronous failures; a one-shot `NATIVE_CONTEXT_LOAD_ASYNC` message records asynchronous load/storage failure. Incomplete observations still fail closed. No queue became unbounded, no committed journal/reward was removed, and no new writer or ledger was introduced. The exact condition at the historical log instant remains unknowable from that log; future occurrences are distinguishable.
