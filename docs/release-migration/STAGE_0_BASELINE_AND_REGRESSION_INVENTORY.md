## A. Native patch boundary — confirmed release mismatch

`PackboundNativeMutationBridge.tryInstall` (lines 17–35) loads `NativeMutationHook`, hashes its **code-source file**, and requires SHA-256 `a032a64e...`. On 0.7.0 the server supplies no such class, so the loadable copy comes from the deployed plugin JAR with hash `3b80550c...`. The exact condition throws `PACKBOUND_NATIVE_PATCH_VERSION_MISMATCH`; the 19:19 server log line 287 and client log lines 445–446 show `RPG_PACKBOUND_NATIVE_PATCH_INVALID promotion=false`. The old pre-release server has the expected hash; the stock release server has no patched references in `ChangeStatInteraction`, `ChangeStatWithModifierInteraction`, `ClearEntityEffectInteraction`, `DamageEntityInteraction`, or `LaunchProjectileInteraction`. Binary inspection found those references only in the patched pre-release server. **Root cause: the installed release server does not have the version-pinned native instrumentation; the plugin's compiled hook types cannot replace it.** Whether those old hook interfaces are source/semantic compatible with 0.7.0 is `UNVERIFIED` and must be checked against the actual release classes before a new patch is designed. Changing the hash or forcibly installing the old hook would not restore absent native call sites.

`HyArpgPlugin` lines 927–973 install `NativeProjectileReceiptHook` and `NativeDamageReceiptHook` **only if** Packbound installation succeeds. The same block calls `nativeBasics().configureNativeDamageReceipt(false)` on failure and constructs `NativeEnemyBirthOwner` with promotion enabled only when all three hooks are present. Thus the release capture proves a disabled Hywind original-hit receipt route and disabled native Elite promotion gate (`RELEASE_FAILED`), but it does **not** prove all ordinary native weapon damage is cancelled. `NativeBasicAttackObserver.Start/Before/After` remain registered (plugin lines 857–859), and their separate native leaf behavior needs a hit/Health capture. Preserve the existing Packbound, receipt, and fail-closed owners; Stage 2 should validate and adapt the exact native seam rather than adding a competing damage system.
