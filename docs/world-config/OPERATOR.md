# Hywind world configuration — R237

The active RPG save uses `Saves/RPG/world-config.json`. On first R237 startup Hywind creates it with accepted R235 defaults and imports the old `world-spawn-density.json` multiplier (8× on the current RPG save). The old file remains intact for recovery. Thereafter the save-root file is the only authoritative density value. Edit the JSON while the world is running, then run `/rpg worldconfig reload`; `/rpg spawns <0.25..8>` writes the same JSON field atomically. `/rpg worldconfig status` shows active revision, density, population policy, and per-environment native counters. Both commands require their own operator permission.

## Bound controls

| JSON path | Existing consumer | Timing |
| --- | --- | --- |
| `world.nativeEnvironmentSpawnMultiplier` | `NativeWorldSpawnDensity`, native per-environment target and native global cap | Reload or `/rpg spawns` projects to loaded worlds; native tick maintains it |
| `spawnPopulationBalance.enabled`, `hostileTargetShare`, `wildlifeTargetShare` | `NativePopulationBalance` projects per-role `WorldNPCSpawnStat.expected` before `WorldSpawningSystem` | Native selection, at most once per second per world |
| `monsterRarity.enabledForNewSpawns`, per-era Champion/Unique chances and affix counts | `EnemyBalance`, `NativeEnemyBirthDecision`, `EnemyBirthPlanner` | New natural births only |
| `packs` sizes and caps | `EnemyBirthPlanner`, `EnemyPackCapacity` | New reservations; existing durable packs grandfathered |
| `combat.rarityStatFactors` | Shared `EnemyBalance` stat providers | Newly generated actors |
| `monsterAffixes.randomWeightMultipliers`, `randomlyEligibleAffixesDisabled` | Existing `EnemyAffixSelection` legal-set enumeration | New random affix rolls; explicit QA selections still require native compatibility |
| `newImmunityGrants.perEra` | Existing `EnemyImmunitySelection` | New births; Normal zero is enforced by the shared balance contract |
| `rewards.xpBonusPerAffixBeyondFirst`, `equipmentQuantityBonusPerAffixBeyondFirst` | Frozen `EnemyRewardContext`, existing XP and gear quantity receipts | New births only |

Default Champion/Unique chances remain **1.6%/6.4% Normal, 2.8%/11.2% Nightmare, 4%/16% Hell**. Super Unique is still authored only. The shipped 65/35 target is a *soft role-selection target among eligible hostile and terrestrial wildlife entries in each native environment*. These figures are not a guaranteed live actor ratio.

The parser requires all published fields, rejects unknown fields and invalid combinations, and never accepts an inert tuning key. Reload builds and validates a candidate before publishing it; invalid input leaves the previous active snapshot in force. A content hash gives each changed enemy balance a distinct revision, archived under the RPG mod data directory. Existing actors and durable encounters retain their recorded balance revision on rebind. Save, active actors, encounter receipts, and pack identities are not rewritten. The JSON `configRevision` is an operator label, not a manual balance migration mechanism.

## Native population binding

The installed pre-release native `WorldEnvironmentSpawnData.updateExpectedNPCs` divides its environmental member target across `WorldNPCSpawnStat` entries by native weight. The native job picker uses each stat's `getMissingCount` plus spawn-parameter eligibility, and native `WorldSpawnJobSystems` still executes and accounts for flocks. Hywind uses the public `setExpected` seam to redistribute **only the controlled, currently eligible per-role member targets**. It keeps total expected population and the relative native weights within each category. It does not synthesize jobs, alter jobs already in flight, bypass native capacity or placement, raise spawn-work budgets, or despawn wildlife. A category absent at the current time/light/terrain eligibility leaves native targets unchanged; a desired increase above 8× its native class share also fails closed to native targets.

The pinned installed `Assets.zip` audit is in [native-world-role-audit.json](native-world-role-audit.json), generated by [Audit-WorldPopulationRoles.py](../../tools/Audit-WorldPopulationRoles.py). It classifies 156 exact native world-spawn IDs: 78 HOSTILE, 32 WILDLIFE, 16 AMBIENT_AVIAN, 30 OTHER. Hostile flyers such as `Eye_Void` remain HOSTILE. Passive avians retain their native target and still consume native environmental capacity and work budget. Aquatic roles and unknown IDs remain OTHER under native weights. The audit records each role's native attitude, group, movement mode and spawn sources. Hytale's expected/actual values count individual NPC members, including flock members; its own min-flock placement/fit checks remain authoritative. Mixed or unknown roles must be inspected in the audit and trace; runtime classification never uses display names or temporary combat targets.

At full native capacity, changing expected role shares does not immediately free slots. New admissions wait for native despawn/death and placement opportunity. `/rpg worldconfig status` reports native actual/expected and headroom separately from class actual counts and class selection targets. `/rpg spawntrace start` captures bounded native job, Elite fallback/rollback, global population and `POPULATION_WEIGHT` events. These diagnostics distinguish selection policy from published actors. They do not establish a measured connected 65/35 ratio without gameplay observation.

## Explicitly unsupported proposed controls

The original `hywind-world-config.proposed.json` is a proposal, **not** a drop-in schema. Its flat rarity rates conflict with the approved R235 defaults. The installed native job API has no proven pre-budget wildlife admission hook, so `wildlifeSoftUpperShare=0.4`, `RESERVE_HOSTILE_HEADROOM`, and `DECLINE_NEW_WILDLIFE_ADMISSIONS` are not implemented or accepted. There is no live 40% threshold or forced population quota. Per-era generic Health/damage tuning, per-era XP/equipment/learning multipliers, equipment drop-chance multiplier, encounter-rank spawn-weight multiplier, `roleOverrides`, `worldOverridesByWorldId`, and a JSON trace switch lack a verified single authoritative consumer and frozen-receipt semantics; the parser rejects them. The existing `/rpg spawntrace` command is the trace owner. Native per-environment density overrides remain native and are multiplied by the save-wide value, never erased.
