# R214-U7P5 connected QA follow-up

## Scope and implementation

- Unique QA packs now attach their already-selected leader and MINION roster to one Hytale `FlockPlugin` group through `FlockMembershipSystems.join`. The flock uses the installed `Group_Small` or `Group_Large` asset and is non-serialized with the transient QA actors. Hytale's membership systems own leader/member state and removal. The Trork idle-motion overlay prepends the installed `Template_Instruction_Flock_Motion` reference ahead of its unchanged spread-out/wander motions, so only an actor that is a flock follower and outside the native leash range seeks the leader. The original Trork combat instructions and 27 ME affix implementations were not edited.
- QA role resolution now uses the authored `EnemyRewardRegistry` concrete role/alias catalog. Existing pinned native bindings take precedence. Other catalog roles receive an action-free QA binding with only shared passive capabilities; no direct-hit affix is falsely advertised. Hostility is still checked from the spawned actor's native `WorldSupport`, and the existing authored profile planner and transient encounter backend remain the owners. The native `SpawningContext` model supplies the bounding box for QA placement.
- `/rpg spawn` suggests concrete catalog IDs, rejects family-only terms with matching examples, and accepts `random` from the same pinned catalog bindings. Empty affix arguments continue through the existing compatibility selector. Explicit incompatible IDs continue to fail with the exact alias and ME ID. No affix-specific QA implementations were added.
- The QA native healthbar now logs final `UIComponentList` presence, live native Health/max, and active-world `Combat.DisplayHealthBars` after birth publication. On an actual positive damage receipt it logs the live Health and list again. The installed `Default` gameplay config omits a Combat override, while the installed SDK's `CombatConfig` constructor defaults `displayHealthBars=true`. Trork role assets contain no `HiddenUIComponents`; Larva_Void and Template_Predator do, so their final runtime list must be observed. Hytale's `UIComponentSystems.Update` queues `UIComponentsUpdate` to tracking viewers, and `EntityStatsSystems.EntityTrackerUpdate` queues `EntityStatsUpdate` after stat changes. A connected client still needs to show whether it renders the native bar; this build does not restore projected CustomUI bars for QA actors.

## Production boundary

`EnemyBirthPlanner` already selects compatible affix sets for production Champion/Unique and does not roll Super Unique. Natural promotion remains enabled for the certified Larva binding. Trork Warrior and Skeleton Scout stay disabled in production: the integration audit records an uncertified natural Trork spawn job and incomplete Scout projectile/reload proof. Campaign Golems remain authored-final. The QA catalog fallback is deliberately not a production binding; widening it would silently claim action, flock, and reward guarantees that have not been proven for those native jobs.
