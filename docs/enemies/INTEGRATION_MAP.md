## GAP-001 — missing authoritative Physical Defense contract

Architecture ME-004 requires Defense 100 -> 140/160/180 and the existing mitigation curve once. ME-025 requires Defense 200 -> 150 in Hell, recomputed to 75 when baseline changes to 100. Neither the input architecture nor the inspected runtime supplies a Defense-to-mitigation curve or role Defense baselines. ME-021 Empowered Minions uses Health/damage/movement and is not affected by this Defense gap.

Evidence:

1. `docs/gear/stage-3-affix-dispositions.md` already records WA-069, WA-070, WA-071 and WA-115 as lacking an authoritative Total Defense scalar/mitigation contract. It explicitly forbids substituting native protection percentages. WA-138 Armor Break is also missing its runtime adapter.
2. `src/main/resources/rpg/gear/native-bindings-v1.json` records the same unavailable Total Defense owner for shields. Authored `shieldDefense` numbers exist in gear bases, but an authored field is not a damage consumer.
3. `GearAffixRuntime.protection` consumes `protectionPoints`; GA-159/160 contracts explicitly say they do not add Defense rating. `DerivedStats` has no Defense field. `IronSentinelStatProjection` combines protection fractions and does not implement the missing scalar/curve. `IronSentinelAffixes` names ARMOR_BREAK but excludes it from `ADAPTED`.
4. Native `DefaultEntityStatTypes` and installed `Server/Entity/Stats` do not provide Defense. `ItemArmor` and `DamageSystems.ArmorDamageReduction` consume flat and multiplier resistance modifiers, not the specified Defense contract. Native bytecode evidence is saved separately.

Resolution (owner instruction, 2026-10-02): implement Master Affix v1.0 section 7, D01, from `C:/Users/Zemio/Downloads/Master_Affix_v1.0.md`. No newer accepted implementation was found. This explicitly authorizes the missing **shared Hywind Defense owner**, not unrelated Master Affix features. The earlier GAP-001 observations in the table describe the audited starting state; the contract gap is now resolved.

`K = 100 + 10 * clamp(authoritativeCombatLevel, 1, 99)`, `Darmor = K*pArmor/(1-pArmor)`, `Dtotal = max(0,(Darmor+Dshield+Dother)*(1+globalDefenseIncreased))`, `Deffective = Dtotal*(1-winningDefenseBreakFraction)`, `pManaged = clamp(Deffective/(K+Deffective),0,.60)`. Use existing resolved managed armor including GA-159/160; do not enable additional gear affixes. Player level comes from `RpgLoadoutService`, NPC level from the encounter resolver. Preserve native cause-specific flat protection, nonmanaged effects, block and immunity. A native cause's existing multiplier is normalized with the same invertible mapping, with baseline parity verified separately from the managed 60% cap.

Implementation seam: `combat/defense/DefenseView` performs the shared calculation; `HytaleGearEquipment.project` replaces its old managed protection projection with this result using the **same** native effect and quantization. It never adds a second damage multiplier. The owner-corrected Stone Skin supplies additive Dother (GAP-004); Armor Breaker supplies the strongest live break input to this owner. Timed applications must remain source-owned with independent expiries and recompute against the current baseline. NPC native cause integration and timed source admission still need implementation and route verification. Empowered Minions has no Defense input.

Finite modifier extraction: extend `FiniteSupportEffects` with typed, content-independent `DEFENSE_BREAK` and `DIRECT_WEAKEN` stat entries. They share that owner's expiration, bounded admission and cleanup, but do not manufacture a `SkillExecutionContext` or add values to the Skill profile enum. Each source retains its own expiry; the strongest fraction is read at projection time. The native gear adapter reads the winning Defense break from this same support owner immediately before native armor filtering. ### GAP-002 — missing implementation of approved Fortune Status Escape (contract resolved)

ME section 05.3 requires the merged status chance to pass through **existing Fortune Status Escape**, and section 06.28 requires preserving that shared owner. Searches of the current Java runtime, combat balance resources and repository documentation found no Fortune Status Escape implementation, probability, eligibility rule, cost or cooldown. `StatusService` implements canonical status timers/control admission; `DerivedStatService` and current resource owners do not provide a Fortune escape consumer. The only production Java Fortune references found are gear-quality eligibility metadata, which is not a status escape implementation. Master Affix v1.0 supplies the Status Resistance/Penetration equation but not Fortune Escape.

Resolution (owner instruction, 2026-10-02): the owner supplied the accepted v1.7.0 Fortune Break contract. `ProgressLuck = 10 + AllocatedLuck`; qualification requires no spent STR/DEX/INT/WIS points and ProgressLuck >= 400. Unspent points and external/gear Luck do not enter this calculation. `Fortune = clamp((ProgressLuck-300)/200,0,1)^4`, with all gameplay chances zero while dormant. Status Escape is one roll at `.20*Fortune`, after protection/immunity and a successful normal status chance, before any stack/refresh/threshold/control mutation. No cooldown. Exclude scripted states, self states, Taunt's override channel and explicit `NoFortuneEscape` sources.

Implementation seam: keep the anchors/exponent/chance in `combat-kernel-v1.json`; derive Fortune from the existing saved allocation record through the shared attribute owner, never the gear-adjusted combat snapshot. Extend `StatusService` with the shared post-success admission gate and use the combat kernel's injected RNG. Existing Skill status adapters and ME packages call the same gate; periodic projection and Chill threshold conversion do not roll again. Admission returns `FORTUNE_STATUS_AVOIDED` without publishing a mutation. This authorizes the missing shared contract only, not a new avoidance Skill or additional Fortune features. Native ME status routes remain required integration work.

- Current difficulty channel enum is FIRE/COLD/LIGHTNING/WIND/VOID/NATURE/NECROTIC/POISON. ME canonical channels are PHYSICAL/WIND/WATER/FIRE/EARTH/LIGHTNING/VOID. Existing saves and native cause aliases must be migrated through the current resistance owner; a second elemental owner is prohibited.

Gear WA-064/079 are recorded as missing adapters. The ME chance formula is specified; implementing the narrow admission extension must preserve existing status semantics and cannot silently enable unimplemented gear affixes.
- `FiniteSupportEffects` and `SupportRuntime` currently require Skill execution contexts. Their underlying primitives need extraction or overloads; fake player Skills/Passives are not an acceptable adapter.
- Native NPC vector/root/projectile/recovery bindings remain unproven. Native API availability and standalone arithmetic tests are insufficient to claim certification.
- Package manifest/assets still require an installed-version validation pass after compilation. Compile success does not establish client rune codec compatibility or role-asset certification.
