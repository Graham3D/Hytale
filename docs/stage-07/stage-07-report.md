## Installed API audit and implementation reasoning

`evidence/stage-07/api/` contains exact `javap -c -p` output and the installed JAR
hash, generated by `Capture-Stage07Api.ps1`. The audit covers ProjectileModule,
StandardPhysicsProvider/Config/TickSystem, ImpactConsumer, EntityRefCollisionProvider,
PierceProjectile, TransformComponent, physics.component.Velocity, CommandBuffer,
DespawnComponent and native provider states. An initial guessed Velocity namespace
did not resolve; archive generation was corrected after enumerating the installed
JAR. No nonexistent API is invoked by the implementation.

The existing seven RPG projectile configurations still carry empty `Interactions`
objects. They supply native models/physics only. RPG continues to calculate and
apply payloads through the existing damage adapter; there is no parallel native
damage, projectile resource cost or cooldown added by this cohort.

Three details in the installed physics implementation matter:

1. Without PierceProjectile, an entity contact sets the provider inactive before
   the impact callback. With PierceProjectile, native motion can continue and the
   component marks visited entity references. The native component's distance
   check is displacement from its origin, not accumulated path. RPG therefore
   retains its own authoritative accumulated path and lifetime accounting.
2. The native tick examines only `getContact(0)` for its entity impact callback.
   Merely enabling native Pierce could skip closely packed bodies crossed in a
   single step. Modified carriers additionally sweep their actual collision box
   against bounded, actual hostile NPC boxes, sorted by entry fraction and stable
   UUID. The sweep calls the same contact/payload path; it does not create a second
   damage engine. Previously hit bodies are skipped. A redirect or consumed parent
   stops processing contacts from the old trajectory. Candidate overflow rejects
   the operation rather than silently truncating to arbitrary targets.
3. Native `endCourse()` sets inactive, invokes the callback with neither block nor
   entity, then queues Despawn and finishes its physics step. Terrain exhaustion
   may also use this path. Treating every null/null callback as terrain would
   wrongly revive lifetime/velocity exhaustion; treating every one as cancellation
   would prevent Return after a real terrain stop. The adapter captures the
   provider's actual `isBounced`/`bounceBlockPosition` evidence. Modified-carrier
   callbacks are deferred through two FIFO CommandBuffer enqueues so native
   post-callback writes finish first. Only an evidenced terrain ending may have
   that course-end despawn removed before a bounded continuation. Non-terrain
   course endings cancel. Stale callbacks check carrier identity and motion
   revision. No replacement entity or new gameplay effect is spawned to bypass
   native cleanup. The unmodified Stage 05 callback timing remains unchanged.

These statements describe inspected bytecode and adapter structure. The isolated
server does not cast projectiles, so it does not prove this callback choreography
works during a connected fight. That distinction is intentionally explicit.

## Cohort A mechanics

`CompiledSkillPlan.projectileModifiers()` derives typed budgets from the compiler's
validated, deduplicated passive order. The continuation planner runs only after
the accepted direct hit payload: **Pierce -> Fork -> Chain -> Return**. It has no
resource, cooldown, asset lookup or damage responsibility.

- **Piercing:** two additional enemy-continuation credits. A stable UUID can be
  accepted once per outbound leg; retaining it for the whole leg is stronger than
  the minimum 0.10-second ignore. The native component prevents that body stopping
  motion; the RPG ledger prevents duplicate payloads.
- **Fork:** after Pierce is exhausted, consume one Fork credit and atomically
  reserve two children at horizontal -20/+20 degrees. Elevation and speed are
  preserved. Each inherits the remaining range/time, offensive snapshot,
  rootCastId/skillInstanceId/correlationId and visited outbound targets. Each gets
  its own projectile ID and incremented generation. Fork is zero in both children;
  already-spent Pierce is not replenished. Original maximum distance is retained
  separately for a later Return. Failure to admit the pair creates neither child.
  A native partial-spawn exception removes every spawned child and its registry
  ownership before consuming the parent.
- **Chain:** at most two redirects to the nearest visible, unvisited target within
  eight metres, with stable UUID tie-breaking. The carrier flies toward that target;
  the planner does not teleport it or immediately apply damage. No range, lifetime
  or Fork budget resets. A missing legal target permits Return/termination.
- **Return:** forward termination consumes the one Return credit. The live caster
  position is consulted each update. Speed is unchanged; return maximum distance
  is the original compiled projectile distance and return lifetime is D/s + 0.10 s.
  It has a separate hit ledger but cannot restart the forward continuation chain.
  Solid terrain or the first crossing into 0.5 m of the caster terminates it. A
  swept sphere entry clips the leg before the caster, avoiding damage beyond a
  caster crossed between ticks. Range clipping also occurs before supplemental
  contacts; native overtravel does not authorize out-of-range payloads.

Native callbacks and owner ticks sample one monotonic clock, so redirects cannot
skip an elapsed tick or charge it twice. Fork inherits remaining time without
rounding it upward. Native timestamp values need not be positive; finite spatial
and duration inputs are validated. Total path/time records include ancestor travel
as well as the current forward/return leg. Lifetime expiration remains finite even
when a target cannot be reached. Native guard limits are deliberately looser than
the RPG leg limits and never substitute for them.

## Root ownership, safety and shared corrections

`ProjectileLifecycleRegistry` now retains root-lifetime spent effects and promised
Echo launches instead of inferring budget from the current number of carriers.
Terminating a parent or short-lived child does not refund its spawned-effect cost.
The cap is 48 effects/root, generation 3, at most 16 triggered-secondary allowance,
24 live/promised carriers per owner and 512 globally. Cohort A does not create
triggered-secondary payloads. Batch admission is atomic and conservative: a Fork
must fit while its parent is still owned; it cannot evict another root to fit.
Root seen-ID sets reject reuse while the root remains alive. The input/execution
authority still owns root replay rejection after all root state has been drained.

Echo is a derived generation-one release, not a second generation-zero root.
Its promised slot survives early primary termination. Scheduled-release rejection
calls the native port's `abandonRelease` hook to clear remaining root promises;
owner cancellation clears active and pending-only roots. Native removals without
an impact also close registry ownership. Owner teardown drops registry promises
before native removal and dispatches cross-world removals to the owning world
thread. No persisted native Ref or command buffer is added to player state.

The native direct-hit adapter previously checked NPC existence, Health and
invulnerability but not native hostility. It now checks the same installed
WorldSupport hostility boundary as the swept and chained queries. This closes a
demonstrable shared friendly-target gap, rather than letting the first native
callback damage an NPC which the continuation query would reject. Players are
not introduced as PvP targets. No Stage 04/05 coefficient, cost, regeneration,
cooldown, status duration, equipment profile or projectile asset is rebalanced.

R020 native Health/Mana/Stamina ownership, native Signature Move, Ability2/Ability3
projection, unsupported Ability4, current XP artwork and CanvasUI remain untouched.
