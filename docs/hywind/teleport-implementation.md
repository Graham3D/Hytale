# Teleport implementation delta

## R251 diagnostic QA candidate

The October 10 connected trace showed five `TELEPORT_NO_VALID_SURFACE` rejections and one `TELEPORT_REQUIRES_GROUND` rejection. It did not record the aim or the failed target-selection stage. R251 preserves the R250 collision and gameplay rules and adds a bounded `TELEPORT_TARGET_REJECTED` skill-trace event for each surface rejection. The event records the actual failed stage, player feet, head aim, effective range, first contact, collision normal, and hit fraction. Normal rejection codes remain unchanged. Deterministic tests exercise the selection rules with a terrain fixture; native collision behavior still requires connected QA. R251 is a diagnostic build, not a confirmed Teleport gameplay fix.

Teleport keeps the existing `rpg.skill.teleport` identity and native equipped skill input. The previous 14 block, 16 Mana, 8 second, short dash runtime was replaced with an instantaneous native `Player.moveTo` cast. It starts at 10 blocks and 20% of total maximum Mana, gains one block and loses one percentage point every even effective rank, and caps intrinsic scaling at rank 20. Base cooldown is 2.5 seconds. Long Reach multiplies the structural range after the cap; Second Wind, Efficiency, Lifeblood and Attunement use the existing charge, resource and passive owners. All other passives are ineligible because the skill exposes no damage, duration, cast-time or traversed-path payload.

The server raycasts from the authoritative head direction to the first solid face, resolves top faces directly and side faces to the top of their targeted solid column, then validates 3D range, five-block upward limit, loaded terrain, four-corner ground support, hazards and full native body clearance. Airborne activation is deferred because the current movement state does not provide a persistent grounded-elevation reference. The summon registry supplies all active owned leases in the same world; their positions are planned and checked before resource payment. The existing entities are moved, preserving identity and native state. The landing particle system contains exactly the installed `MagicPortal_StonesSpawn` spawner and is emitted once at destination support elevation plus two blocks.

The `/rpg teleport` operator QA grant is the only new acquisition path. The proposed enemy acquisition source remains unassigned. Connected game QA is required for client replication, actual particle rendering, native terrain collision behavior, claims or region policies if enabled, and simultaneous combat/movement interactions. This implementation is based on the exact source commit embedded in the deployed R249-U7P5B JAR, and its next revision is R250-U7P5B.
