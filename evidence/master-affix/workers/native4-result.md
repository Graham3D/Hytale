## WA-155 / D11 calibration

- Inspected the **pre-release** server `ProtocolCodecs.COLOR_LIGHT`: asset `Radius` uses `Codec.BYTE`, with JSON accepted range `-128..127`. Packet `ColorLight.radius` is one byte. `Assets.zip` has authored item light radii 0, 1, 2, 3, 4, 5, 6, 8, 9, 10, 12 and 18; three iridescent crystal assets author 18. This disproves an asserted **asset codec** maximum of 15, but does **not** disprove a client renderer clamp at 15. The installed asset tree and client data expose no light shader/source or metres-per-unit conversion. No binary was modified.
- `NativeAffixLightProjection.Calibration` now records an explicit renderer ceiling (1..127) and metres per native unit; `fromSystemProperties()` fails closed until both `rpg.gear.lightMetresPerNativeUnit` and `rpg.gear.lightMaximumNativeRadius` are supplied. The projection reports target **metres** separately from effective **native units** and preserves the normal packet baseline if a measured renderer ceiling is below it. It no longer assumes 255 supported units.
- `/rpg geartrace light` displays target metres, effective native units, and actual packet units from the actor component. `/rpg geartrace lightprobe N` temporarily applies white actor light at `N=1..127` native units and restores its prior component with `N=0` or after 30 seconds; it refuses an active WA-155 projection and will not overwrite a competing native writer on restoration. `/rpg geartrace lightcal r1:m1,r2:m2,r3:m3,ceiling,toleranceMetres` fits three measured observations and rejects a non-linear mapping beyond the supplied tolerance. These are diagnostic inputs, not a fabricated calibration.
- Connected calibration protocol: use the same dark, unobstructed world position and no held light; mark metre intervals with blocks. Probe radii 1, 4 and 8 separately, measure visible falloff in metres and fit them with `lightcal` using a recorded measurement tolerance. Probe 15, 16 and 18 under the same conditions to determine the last radius that changes visible falloff; enter that **measured** ceiling, not the server codec's 127 bound. Record client/build hash, graphics settings, baseline and repeat measurements with a normal torch plus the affixed item. If the curve is non-linear or light is capped before an affix can add a visible step, D11 is still unresolved. The byte codec alone cannot establish rendered metre scale or renderer cap.

The main owner must bind/register that system with a measured `Calibration` and display these two units explicitly. WA-155 remains gated pending those observations and connected QA. At an actual renderer ceiling, a positive bonus can saturate; this is an unresolved visible-effect case, not reported as success.
