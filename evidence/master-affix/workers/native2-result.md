## Native API proof

- Installed `0.7.0-pre.4` `ProjectileModule.spawnProjectile(UUID,Long,Ref,CommandBuffer,ProjectileConfig,Vector3d,Vector3d,float,float,long)` was inspected with `javap -c`. The **ninth** argument multiplies `ProjectileConfig.getLaunchForce()` before `PhysicsConfig.apply`; the eighth scales the model/hitbox. Pass `1f, quote.speedMultiplier(), millis` to change native replicated motion without changing hitbox size. Existing `ProjectileInteraction.firstRun` calls the overload without floats, fixing both at 1.
- `StandardPhysicsTickSystem` reads native `Velocity`, `TransformComponent` and `StandardPhysicsProvider`; the new registered systems declare dependencies before/after it. The before system uses the same TPS/time-dilation duration as native physics. `DespawnComponent` and `Store.removeEntity` are supported, so the post-tick system terminates the actual projectile.
- Installed `DynamicLight.setColorLight` marks the component network-outdated. `EntitySystems.DynamicLightTracker` consumes that flag and queues ordinary `DynamicLightUpdate`. `ColorLight.radius` is one byte; fractional byte resolution is impossible. `DynamicLightSystems.Setup` copies `PersistentDynamicLight` into `DynamicLight` on entity add. The byte-to-metres renderer calibration is **not exposed** by installed public server API; no value was invented. `Calibration` is an explicit input.
- Installed stock `Item.getResourceTypes`, `getMaxStack`, `getWeapon`, and `getArmor` are public. The source-authorized spatial stock flow already holds protected sources and performs preflight, durable receipt, bag publish/save, source removal and recovery. This worker added admission only, not custody.

## Remaining concrete boundaries

- The stock API does not expose an already used per-player LOS/claim predicate in `HytaleGearLoot`. The owner must add one at scan and revalidation, and use the same selected source throughout. The current explicit material allowlist accepts resource-typed `Ingredient_*` and `Ore_*` stacks only. Other material taxonomy and currency source classification require an audited allowlist; currency is withheld pending the durable receipt design.
- Post-physics transform deltas are a conservative path ledger. A bounce or curved move within one native tick can travel farther than its start/end chord; the before-physics limiter bounds the straight final step only. Full WA-016 gravity/homing/bounce closure requires a native swept-motion tap or a managed collision-preserving physics extension at `StandardPhysicsTickSystem` rather than counting only transform endpoints. The new system must remain gated until that is solved.
- The server JAR confirms ColorLight byte quantization and normal replication, but cannot establish rendered metre scale, standalone hue when normal light has no RGB, or client-visible prediction equivalence for modified spawn force. These require owner calibration/QA. No light-radius claim is made complete.
- `NativeAffixSpatialAdaptersTest` is deterministic contract coverage, not a registered `GearNativeItems.effects` or transaction round-trip test. Main must run registered positive/control/negative QA and the complete simulator before any capability gate change.
