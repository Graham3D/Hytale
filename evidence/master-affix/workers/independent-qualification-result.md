# Independent affix qualification review — 2026-09-30

## Authority and verdict

Read-only review of the current task attachment, `tools/affix-proof-map-v1.json`, current production wiring, current tests, and existing JUnit XML. The task accepts either a measured effect in the real Hywind owner **or the intended supported Hytale-facing adapter**, with deterministic positive and negative simulator proof. Connected owner gameplay QA comes later. A native ECS world, contact, or final HP observation is therefore not a universal offline prerequisite. A value computed only for UI, a manually supplied desired output, a queued child with no consumer, or a stub that returns `true` for native application is also not enough.

The proof map has 160 ID entries and 80 `specificGaps` entries; it currently has no `deferredAcceptance` property. Its repeated `qualificationHoles` asking for native ECS contact/final HP overstate the offline gate wherever the shared production adapter and a measured adapter outcome are already tested. Conversely, several `specificGaps` are real and should not be erased by changing terminology. `GearAffixRuntime.ENABLED` currently has **159 IDs; WA-155 is intentionally absent pending owner-measured light calibration**. This review makes no `160 FUNCTIONAL` claim and does not promote any row from code inspection alone.

Existing XML at the review point reports 0 failures for focused `NativeAffixTwinCommitTest` (2), `NativeAffixDefenseContactTest` (5), `MasterAffixResourceCompletionTest` (10), `MasterAffixSummonCompletionTest` (7), `MasterAffixSentinelRecoveryTest` (2), `MasterAffixEconomyCompletionTest` (3), `MasterAffixEquipmentSimulatorTest` (320), and native action/carrier codec qualification (4/6). These artifacts establish focused passing evidence, not a fresh complete passing gate. No build or Gradle run was performed in this review.

## Cross-cutting release notes

1. The shared snapshot and legal-carrier suite is necessary but not sufficient. Preserve source identity through hit, status, summon, child and reward callbacks; committed attacks/projectiles/deaths must use captured state while future events lose unequipped or invalid gear. The remaining callback tests above should explicitly assert this at their nearest existing owner seam.
2. A native codec decode proves the configuration can load. It becomes adapter evidence when combined with a real production selector and a measured output from that adapter, as in the protection lookup and accepted WA-141 offhand calculation. It cannot stand in for a native `addEffect`, skill child, stock transfer, or damage recipient result where those are the intended effect.
3. Do not weaken the positive/control/negative matrix, count a manually assembled desired result, or change catalog identity/eligibility to make a test pass. Fix only affix-owned production seams and focused simulator tests. The existing coverage manifest/proof map needs regeneration **after** the remaining tests and a fresh full passing gate; its current candidate/gated labels and old `specificGaps` should not be treated as live test results.
4. The task attachment requests a server smoke, but the current user instruction explicitly prohibits game/server/auth/deploy in this review. No smoke was attempted or inferred. The owner performs connected QA later; the offline qualification should be completed with deterministic production-owner tests first.

No source, gate, fixture, manifest, test, or audit was edited by this review. No Gradle, game, server, auth, deploy, commit, or agent was run.
