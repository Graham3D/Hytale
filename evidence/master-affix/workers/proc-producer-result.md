# Proc producer handoff (2026-09-30)

Scope: `docs/MASTER_AFFIX_SCOPE_CORRECTION.md`. No base skill, ordinary skill chance, authored proc metadata, item payload, channel split, or consumer binding was changed. No Gradle, game/server/auth, deploy, commit, or worker was run.

## Implemented

- `NativeItemProcBudget` now accepts an eligible area set before child damage. It sorts UUIDs, reserves an equal item-only share, returns the same share to distinct damage channels of one admitted contact, gives zero to duplicate callbacks or victims outside the set, and never redistributes a cancelled victim's share to a later contact. Source item/revision/root are frozen. Authored sequential strike ordinals have separate planned allowances inside the unchanged cast root. Paid interval plans cap at `min(1, actualPaidDeltaSeconds)`; unpaid windows return zero. Existing streaming fallback remains bounded for producers without a predeclared set.
- `HytaleSkillExecutionSystem.executeStrikeHit` feeds the existing strike geometry's accepted set after its existing per-hit dedup into that budget before child damage. The contact prefix uses the existing correlation/effect/hit ordinal, so `HytaleDamageLifecycleSystems.Application` delivers the reserved item-only share to the existing receipt consumers. Damage order, skill proc coefficient, skill statuses, root metadata, and channel payload are unchanged.
- `NativeGearAttackAcceptance.selectedAreaCoefficient` reads the native selector's public `SELECT_META_STORE` and `HIT_ENTITIES` after selection and before its forked damage child. It maps selected native network IDs to UUIDs, applies the native selector invulnerability gate and the same hostile/protection checks used by `Application`, and reserves the eligible set. `ManagedGearDamageInteraction` and `ManagedCarrierDamageInteraction` pass that share to `commit`, so WA-136's premitigation Deadly roll and the later item receipt use the same producer coefficient. The owned bomb impact asset uses `AOECircle` with no `MaxTargets` or `HitEntityRules`; the set comes from the existing selector, with no replacement geometry.
- The authored Shortbow Volley assets produce three Left/Center/Right projectile legs at each strength and specify `RpgProcCoefficient = 1/3` on the damage leaf. The existing `ManagedGearProjectile` root uses the forked chain ID, so the three projectile roots are bounded by that authored coefficient. No asset value was changed.

## Remaining qualification limits

- This is offline proof. There was no native selector or damage lifecycle execution in a running Hytale world. A selector that gains victims on a later native tick cannot retroactively equal-share with its first tick; later victims receive zero under the frozen first set. The audited owned bomb selector has no reservoir cap or alternate hit rules, but live single-scan behavior is not proven. Do not mark native AoE fully qualified from these tests alone.
- `ConnectionRuntime.tickField` passes `profile.intervalSeconds()` to `payUpkeep` and calls `hit(..., periodic=profile.channel())` after payment. `HytaleSkillExecutionSystem` routes that channel damage with `periodic=true`; its current adapter creates no gear hit for this path. `HytaleDamageLifecycleSystems.Application`, `NativeGearStatusObserver`, and `GearSignatureBindings` require `Origin.DIRECT` for ordinary item on-hit receipts. The paid interval budget method is tested, but there is no existing eligible continuous **direct-hit** item producer to consume it without a distinct affix-only receipt route. Changing the skill's periodic origin or ordinary proc behavior would violate the scope correction. **Continuous item proc runtime remains unqualified.**
- The native projectile root is per forked projectile. The three-leg Volley bound is proven from the owned authored asset and launch-root source, not from a live projectile batch trace. A changed projectile count or coefficient needs a fresh asset audit.
